This site is a **complete point of reference** for Git. It is written so that anyone can understand it. Short sentences. Simple words. One idea at a time. Git gud, noob.

---

<details class="getting-started-collapse">
<summary><strong>I’m new. Where do I start?</strong></summary>

1. Read [What is Git?](/what-is-git/) — a short answer in plain words.
2. Follow [Getting started](/getting-started/) — install Git and make your first save, step by step.
3. When you need to do a specific thing (for example put your project on GitHub), use a [How-to guide](/how-to/put-project-on-github/).
4. When you need to look up a command, use the [Cheat sheet](/cheat-sheet/) or the command pages in the sidebar.

</details>

## How this site is organized

We use four types of docs. This follows the Diátaxis model. Pick the one that fits what you need.

| Type | When to use it | Where |
|------|----------------|--------|
| **Tutorial** | You want to learn. You follow steps in order. | [Getting started](/getting-started/) |
| **How-to guide** | You have a task. You want to do one thing. | [How-to guides](/how-to/put-project-on-github/) in the sidebar |
| **Reference** | You need a command or a fact. You look it up. | [Cheat sheet](/cheat-sheet/) and [Commands](/commands/status/) in the sidebar |
| **Explanation** | You want to understand how things fit together. | [What is Git?](/what-is-git/), [How the commands fit together](/workflow/), [Why Git feels hard](/why-git-feels-hard/) |

Use the **left sidebar** to jump to any of these. The sidebar is fixed so you can always find your way.
